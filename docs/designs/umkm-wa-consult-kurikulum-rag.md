## Problem Statement

Owner UMKM di nomor kasir WhatsApp sudah bisa catat jual/stok/laporan (Hermes `kasir-tools` → DB). Mereka juga ingin **tanya bebas soal bisnis** (modal, harga, manajemen usaha). Jawaban harus **terbatas ke kurikulum terkurasi** — buku PDF *Manajemen Usaha Kecil dan Menengah* (Purba et al., 2021) — bukan ChatGPT bebas dan bukan RAG atas ledger toko.

## Demand Evidence

- **Lemah / belum terbukti perilaku:** status quo = tanya orang / Google / ChatGPT bebas. Belum ada observasi live owner bertanya tanpa dibantu.
- **Hipotesis produk:** jawaban di nomor kasir yang sama + grounded ke buku = lebih dipercaya daripada ChatGPT generik.
- Gap: fitur “tanya bebas grounded” di WA **belum ON**; Studio notebook RAG di Admin **sudah ada**.

## Status Quo

Owner bingung bisnis → tanya luar app (teman / Google / ChatGPT). Kasir WA hanya dipakai untuk ritual operasional. Nest pernah punya jejak `pendamping` / agentic-ask + curriculum, tetapi inbound prod sekarang **Hermes pipe-only**.

## Target User & Narrowest Wedge

- **User:** owner warung yang sudah allowlisted di kasir WA (bukan kategori abstrak “UMKM”).
- **Wedge v1:** satu perintah WA (`tanya …` / `konsultasi …` / alias `pendamping`) → jawaban **hanya** dari **satu PDF bersama** (URL kurikulum di atas), bukan multi-PDF per tenant.

## Constraints

- Platform locks (eng review Q1–Q4 / L8): stok/harga/omzet = tools→DB only; no MEMORY.md / RAG ledger; satu SOUL shared.
- WA toolsets tetap `clarify` + `kasir` (G13) — tambah tool di set `kasir`, jangan buka coding/browser.
- Jangan revive dual-brain Nest inbound untuk kasir.
- Hak cipta PDF: ingest salinan yang sah ke notebook internal; sitasi ringan (“dari buku Manajemen UKM…”); jangan redistribusi file ke user.

## Premises (agreed)

1. Masalah = saran bisnis di nomor kasir, bukan “cari stok lewat RAG.”
2. v1 = satu PDF bersama, bukan RAG per-tenant dulu.
3. Jawaban via **Hermes tool → Studio RAG yang ada**, bukan vector store baru di Hermes.
4. Kasir tools tetap DB; konsultasi tidak mengarang angka toko.
5. Demand belum kuat — ship wedge kecil, ukur pemakaian, lalu observe.

## Approaches Considered

## Recommended Approach

```
Owner: "tanya gimana atur modal warung"
  → SOUL route → kasir_consult(question)
  → middleware retrieveContext(notebook_kurikulum_id, question)
  → synthesize singkat (Bahasa), sitasi ringan, user_safe
  → WA reply
```

**Build steps (outline):**

1. **Ops:** unduh PDF → upload ke notebook Studio khusus kurikulum (satu `notebook_id` global / env `KASIR_CONSULT_NOTEBOOK_ID`) → pastikan ingest `done`.
2. **Hermes:** tool `kasir_consult` di `kasir-tools` + baris SOUL (*tanya / konsultasi / pendamping* → tool itu; jangan `kasir_get_stock`).
3. **Middleware:** thin authenticated endpoint atau reuse path retrieve yang sudah dipakai pendamping/agentic-ask (`StudioContextService.retrieveContext`) — dipanggil dari Hermes via Kong/service role dengan scope notebook kurikulum saja.
4. **Guards:** jika pertanyaan jelas kasir (stok/jual/omzet) → jangan consult; arahkan tools. Jika retrieve kosong → “belum ketemu di buku, coba tanya lebih spesifik.”
5. **Docs/diagrams:** update L8 (optional later → v1 jalur consult); pitch owner phrase; hermes-architecture.

**Explicitly out of v1:** multi-tenant custom SOP RAG, multi-PDF, sitasi nomor halaman sempurna, HITL mentor.

## Success Criteria

- Owner allowlisted kirim `tanya …` → dapat jawaban Bahasa yang jelas grounded (bukan refuse chat-only).
- Pertanyaan `cek stok indomie` tetap tools→DB (tidak lewat consult).
- Log: retrieve hit/miss + latency; hit rate frase dalam 2 minggu pilot ≥ N percakapan nyata (tetapkan N saat ship).
- Assignment observasi: 1 sesi nonton owner tanya tanpa dibantu.

## Dependencies

- PDF dapat diingest (ukuran ~18MB — cek limit upload).
- Hermes posture / allowlist G13 tetap hijau setelah tool baru.
