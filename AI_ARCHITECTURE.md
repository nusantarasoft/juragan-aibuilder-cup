# AI Architecture: Labeling & Embeddings

This document outlines the architecture and data flow for the AI features in the Nusantarasoft Media CMS.

## 1. System Overview

The system uses a **Retrieval-Augmented Generation (RAG)** pattern where:
1.  **Media Assets** are stored in **MinIO** (S3 compatible).
2.  **Metadata** (Tags, Description) is generated by **Google Gemini 1.5 Flash**.
3.  **Embeddings** (Vectors) are generated by **Google Gemini Text Embedding 004**.
4.  **Vectors** are stored in **PostgreSQL (pgvector)** via Supabase.
5.  **Search** performs cosine similarity on these vectors.

## 2. Data Flow Diagrams

### A. Auto-Labeling Flow (Generate Tags)

Triggers when a user uploads a file with "Auto Label" checked, or clicks "Auto Label" in the UI.

```mermaid
sequenceDiagram
    participant User as Admin UI
    participant API as Middleware (NestJS)
    participant DB as Postgres (Supabase)
    participant S3 as MinIO (Storage)
    participant LS as LabelStudio (Annotation)
    participant AI as Google Gemini API

    User->>API: Mutation: autoLabelMedia(mediaId)
    API->>DB: Fetch Media Record (s3_key, mime_type)
    API->>S3: Get Object Buffer (s3_key)
    S3-->>API: Binary Data (Image)
    
    rect rgb(240, 248, 255)
        Note over API, AI: AI Analysis Phase
        API->>AI: POST /generateContent (Gemini 1.5 Flash/Pro)
        Note right of API: Prompt: "Analyze this image. Return 5-10 tags."
        AI-->>API: JSON: ["sunset", "beach", "ocean", "vacation"]
    end

    API->>DB: UPDATE media SET metadata = { tags: [...] }
    
    opt Send to LabelStudio
        API->>LS: Create Task (Image URL, Predicted Tags)
        LS-->>API: Task ID
        API->>DB: Link Task ID to Media
    end
    
    API-->>User: Return Tags + LabelStudio Link
```

### B. Embedding Generation Flow (RAG Indexing)

Triggers when a user clicks "Generate Embeddings" or automatically after upload.

```mermaid
sequenceDiagram
    participant User as Admin UI
    participant API as Middleware (NestJS)
    participant DB as Postgres (Supabase)
    participant AI as Google Gemini API

    User->>API: Mutation: generateMediaEmbeddings(mediaId)
    API->>DB: Fetch Media Metadata (filename, tags, description)
    
    alt Short on Metadata?
        Note over API, AI: If description missing, generate it first
        API->>AI: Gemini Vision: "Describe this image in detail"
        AI-->>API: "A beautiful sunset over a tropical beach..."
        API->>DB: Save Description
    end

    Note over API: Construct Context String
    Note right of API: "Filename: beach.jpg\nDescription: A beautiful sunset...\nTags: sunset, beach"

    rect rgb(255, 240, 245)
        Note over API, AI: Vectorization Phase
        API->>AI: POST /embedContent (text-embedding-004)
        Note right of API: Input: Context String
        AI-->>API: Vector [0.012, -0.931, ...] (768 dim)
    end

    API->>DB: UPSERT media_embeddings (id, vector)
    API-->>User: Success (true)
```

## 3. Component Details

### Middleware (`RagService`)
- **Location**: `middleware/src/rag/rag.service.ts`
- **Responsibilities**:
    - Abstraction layer between App and AI Models.
    - Handles S3 file retrieval using `MinioClient`.
    - Manages fallback logic (API Key vs Service Account).
    - Formats text context for embedding.

### Database Schema
- **`media` table**: Stores metadata (`jsonb`), description, tags.
- **`media_embeddings` table**: Stores the vector (`vector(768)`).
    - Uses `pgvector` extension.
    - Linked to `media.id`.

### AI Models Used
- **Vision/Labeling**: `gemini-1.5-flash` (Fast, cost-effective multimodal analysis).
- **Embedding**: `text-embedding-004` (High performance, 768 dimensions).
